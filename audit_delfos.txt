## 3. Common Issues
1. **Database not configured** – All commands that interact with the index or repository fail because `Delfos.Repo` is not started or the `:database` key is missing. |
2. **No projects registered** – `delfos watch` and other index‑based commands require at least one project to be registered via `delfos init <path>`. |
3. **Interactive prompts in non‑interactive session** – `delfos setup` and `delfos integrate` expect user input; when run non‑interactively they keep prompting and eventually error out. |
4. **Missing LLM provider** – `config` shows LLM provider as `local` with placeholder API keys (`sk-loc...-dev`), indicating that no real provider is configured. |

## 4. Suggested Fixes
| Issue | Fix | Notes |
|-------|-----|-------|
| Database not configured | Run `delfos setup` interactively or set `config` file manually (`config/config.exs` or `delfos_config.yml`). Provide PostgreSQL DSN and credentials. | After DB is reachable, commands like `init`, `scan`, `audit`, `summarize`, etc., will work. |
| No projects registered | Execute `delfos init .` from the project root to register the current directory as a project. | Alternatively, specify a path if the project lives elsewhere. |
| Interactive wizard failures | Run `delfos setup` in an interactive terminal, answering prompts. For non‑interactive automation, set the required environment variables or edit the config file directly. |
| Missing LLM provider | Use `delfos config set llm provider <provider>` (e.g., `openai`, `anthropic`). Then set the corresponding API key with `delfos config set llm api_key <key>`. |
| `delfos serve` mis‑usage | Verify that the command is intended; if you want to start the MCP server, use `delfos serve --help` or consult documentation. |
